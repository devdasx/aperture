Unified sheet direction

This is a proposal, not an app redesign. It keeps native bottom-sheet behavior, but gives our shared sheet language stronger hierarchy, better glass layering, cleaner actions, and less heavy copy.

Design rules I would apply
1
Use the system sheet as the chrome.
Keep SwiftUI sheet detents, drag indicator, dim layer, and safe-area behavior. Custom work should live inside the sheet, not replace the sheet.
2
Move from giant page headings to sheet headings.
Use a compact title row for the sheet purpose, then a hero panel only when the sheet needs reassurance or explanation.
3
Use material layers, not flat white cards.
Outer sheet material, inner card material, and an action dock should have different opacity and blur strength so hierarchy is visible in light and dark mode.
4
Pin actions in a glass dock.
Primary and secondary actions stay reachable at the bottom, with the scrollable body above. This solves long-content sheets without hiding the button.
5
Make list rows native-feeling.
Rows need aligned icon slots, subtle separators, status chips, and readable text weights. No oversized centered paragraphs unless the sheet is a one-message alert.
6
Respect accessibility and Reduce Transparency.
The real Swift version should fall back to solid adaptive colors when transparency is reduced, and keep Dynamic Type wrapping stable.
Apple references used
Apple HIG: Sheets - a sheet is for a scoped task related to current context. Apple HIG: Materials - materials create depth, layering, and hierarchy. Apple HIG: Modality - modal content blocks the parent until dismissed.
